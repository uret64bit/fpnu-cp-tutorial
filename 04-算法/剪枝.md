# 剪枝

> [!info] 一句话
> 剪枝是在搜索树上提前判断“这条路不可能/不值得”，砍掉整棵子树——前提是不能误杀正解。

## 为什么需要剪枝

DFS 的搜索树可能大到无法接受。但很多分支一看就知道没希望：和已经超了、位置已经冲突了、当前花费已经比已知最优还差。这些分支不必再往下搜，直接 `return`，就是**剪枝**。

剪枝不改变答案，只减少搜索量。**正确性优先**：宁可少剪，不能剪错。

## 可行性剪枝

当前状态已经违反题目约束，继续走只会更错，立即返回。

例子：从若干个数里选，使和为 `target`（所有数为正）。

```cpp
void dfs(int i, int sum) {
    if (sum > target) return;          // 已经超了，后面只会更大
    if (sum == target) { ans++; return; }
    if (i == n + 1) return;
    dfs(i + 1, sum);                   // 不选
    dfs(i + 1, sum + a[i]);            // 选
}
```

其他常见形式：

- 网格里越界、撞墙、走到已访问的格子；
- 八皇后同一列/同一对角线已有皇后；
- 剩下的元素全选上也不够目标（“预算不够”）。

## 最优性剪枝

题目求最小值/最大值，当前方案的代价已经不可能优于已知最优，直接返回。

```cpp
void dfs(int u, int cost) {
    if (cost >= best) return;          // 已经不比当前最优好
    if (u == target) {
        best = min(best, cost);
        return;
    }
    // 继续扩展……
}
```

`best` 要先有一个合法上界（比如贪心解或直接 `INF`）。如果题目求最大得分，就把条件反过来：`score <= best` 时剪掉。

## 搜索顺序

同一个搜索树，先搜哪个分支，效果可能差很多：

- 求最小值时，**先试代价小的分支**，能更早得到一个好的 `best`，后面的最优性剪枝就更狠；
- 求方案数时，把更可能成功的选择排在前面，可以更快找到解；
- 有时先排序（从大到小/从小到大）再搜索，剪枝效果更好。

## 例子：八皇后

在 $n \times n$ 棋盘上放 $n$ 个皇后，任意两个不能同行、同列、同对角线。按行搜索，每行选一列：

```cpp
int n, ans;
bool col[N], d1[N], d2[N];   // 列、主对角线、副对角线

void dfs(int x) {
    if (x == n + 1) { ans++; return; }
    for (int y = 1; y <= n; y++) {
        if (col[y] || d1[x + y] || d2[x - y + n]) continue;   // 冲突剪枝
        col[y] = d1[x + y] = d2[x - y + n] = true;
        dfs(x + 1);
        col[y] = d1[x + y] = d2[x - y + n] = false;           // 撤销
    }
}
```

这里把“同一行”天然避免了（每行只放一个），再用三个数组剪掉列和对角线冲突。`x + y` 和 `x - y + n` 把两条对角线映射成唯一编号。

> [!warning] 易错点
> - **剪宽了**：条件写错，把仍有解的分支砍掉，答案偏小甚至为 0。
> - **剪窄了**：只剪无关紧要的情况，复杂度没降下来，照样 TLE。
> - **最优性剪枝的界写错**：`>=` 和 `>` 用反，可能漏掉相等的最优解（求方案数时尤其致命）。
> - **忘记撤销**：剪枝判断用的标记没恢复，后续分支状态被污染。
> - **先剪枝后验证**：没有暴力对照，很难发现误杀。

> [!tip] 竞赛提示
> 正确的做题顺序是：**先写暴力 DFS，测小数据**；再加剪枝，用同样的数据对比答案。还可以写一个暴力程序做**对拍**，随机造数据，两边答案不一致就说明剪枝有问题。常见组合：[[DFS搜索]] + [[回溯]] + 剪枝。如果剪枝也压不住复杂度，就要考虑 [[动态规划入门]] 或其他算法。
