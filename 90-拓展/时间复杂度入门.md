# 时间复杂度入门

> [!abstract] 拓展 · 选读
> 这是看懂数据范围、判断算法会不会超时的最小知识。竞赛入门阶段只需会估算数量级，不需要严格证明。

## 为什么需要复杂度

OJ 通常限制 1 秒、2 秒的运行时间。同一个问题：

- $n \le 100$ 时，双重循环 $O(n^2)$ 完全没问题；
- $n \le 10^5$ 时，$O(n^2)$ 就是 $10^{10}$ 次操作，几乎必然超时，需要 $O(n \log n)$ 或更快的算法。

所以读完题，先看数据范围，再想算法。

## 大 O 记号：看增长趋势

$O(f(n))$ 表示“操作次数大约和 $f(n)$ 成正比”，只保留最高阶项，忽略常数。

常见复杂度从低到高：

| 复杂度 | 直观含义 | 典型例子 |
| --- | --- | --- |
| $O(1)$ | 常数时间 | 数组按下标访问 |
| $O(\log n)$ | 每次减半 | 二分查找 |
| $O(n)$ | 扫一遍 | 求最大值、前缀和 |
| $O(n \log n)$ | 排序级别 | `sort`、归并排序 |
| $O(n^2)$ | 双重循环 | 枚举所有数对 |
| $O(2^n)$ | 指数级 | 枚举所有子集 |
| $O(n!)$ | 阶乘级 | 枚举所有排列 |

> [!note] 常数可以忽略，但不能忽略太多
> $O(n)$ 的算法如果常数特别大，也可能比 $O(n \log n)$ 的算法慢。入门阶段先保证复杂度正确，再考虑常数优化。

## 1 秒大概能跑多少

这是一个粗略经验值：

```text
C++ 简单循环：约 10^8 次基本操作 / 秒
```

实际还要考虑输入输出、函数调用、内存访问、递归开销，所以不要卡着上限设计算法。

## 用数据范围倒推

| 数据范围 | 大概可以接受的复杂度 |
| --- | --- |
| $n \le 20$ | $O(2^n)$、$O(n!)$ 的搜索 |
| $n \le 100$ | $O(n^3)$ |
| $n \le 1000$ | $O(n^2)$ |
| $n \le 10^5$ | $O(n \log n)$ |
| $n \le 10^6$ | $O(n \log n)$ 通常可以，$O(n)$ 更稳 |
| $n \le 10^8$ | 简单的 $O(n)$ 也要小心 |

这张表是经验，不是绝对规则。题目给的常数、数据分布、算法实现都会影响结果。

## 空间复杂度

数组占多少内存，可以用：

```text
元素个数 × 每个元素字节数
```

例如：

- `int a[1000000]` 大约占 4MB；
- `int a[100000000]` 大约占 400MB，在 128MB/256MB 的限制下会 MLE。

常见限制：

```text
128MB ≈ 3.3 × 10^7 个 int
256MB ≈ 6.7 × 10^7 个 int
```

递归也会占内存，递归太深可能爆栈（RE）。后续学搜索时会遇到。

## 竞赛提示

1. **先看数据范围，再想算法**，不要写完才发现复杂度不够。
2. 看到 $n \le 10^5$，先排除 $O(n^2)$。
3. 看到 $n \le 20$，可以想搜索/枚举。
4. 不会正解时，先写暴力拿部分分，再优化。
5. 超时先换算法，不要一开始就抠输入输出常数。
