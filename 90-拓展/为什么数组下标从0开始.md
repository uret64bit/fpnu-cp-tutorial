# 为什么数组下标从 0 开始

> [!abstract] 拓展 · 选读
> 这是理解性内容。即使不知道原因，也能正常使用数组；理解了它，`a[i]`、指针和循环会变得更自然。

## 先知道数组是什么

数组是一段**连续的内存**，用来按顺序存放很多个同类型的数据：

```cpp
int a[5] = {10, 20, 30, 40, 50};
```

可以把它想成一排连续的盒子：

```text
a[0]   a[1]   a[2]   a[3]   a[4]
 10     20     30     40     50
```

`int a[5]` 表示有 5 个盒子，合法的下标是 `0`、`1`、`2`、`3`、`4`，**没有 `a[5]`**。

## 下标其实是“偏移量”

数组有一个首地址，也就是 `a[0]` 的地址。访问 `a[i]` 时，程序要计算：

```text
a[i] 的地址 = 首地址 + i × 每个元素占的字节数
```

- `a[0]`：距离首地址 0 个元素，所以偏移量是 0；
- `a[1]`：距离首地址 1 个元素，所以偏移量是 1；
- 以此类推。

下标表示的是**从开头走了多少步**，而不是“第几个”。从 0 开始数，正好和第 0 步对应。

在 C/C++ 中，`a[i]` 本质上等价于：

```cpp
*(a + i)
```

也就是“首地址往后移动 `i` 个元素，再取出里面的值”。这个写法里，偏移量自然从 0 开始。

## 如果从 1 开始会怎样

假设下标从 1 开始，那么每次访问都要先做一次减法：

```text
a[i] 的地址 = 首地址 + (i - 1) × 元素大小
```

这会让每次数组访问都多一步计算，还要额外定义“1 号元素”和首地址的关系。C 语言选择了从 0 开始，后来的 C++、Java、Python 等多数语言也沿用了这个习惯。

## 0-based 和 1-based

两种习惯在算法竞赛里都会遇到：

- **0-based**：下标从 0 开始，C/C++ 数组天然如此。
- **1-based**：下标从 1 开始，方便和题目里的“第 1 个”“第 n 个”对应。

在 C/C++ 里想用 1-based，可以多开一个位置：

```cpp
int n;
scanf("%d", &n);

int a[n + 1];          // 下标 0 空着不用
for (int i = 1; i <= n; i++) {
    scanf("%d", &a[i]);
}
```

> [!note] 什么时候用哪种
> - 普通数组遍历：0-based 更自然，循环写 `i < n`。
> - 前缀和、差分、图论、DP：1-based 有时少写边界判断。
> - **最重要的是保持一致**：不要一半用 0、一半用 1，最后自己都搞混。

## 数组越界

C/C++ 不会自动检查下标是否合法。访问 `a[5]`（数组只有 0～4）属于**越界**，可能读到垃圾值，也可能破坏其他变量，甚至直接崩溃（RE）。

> [!warning] 竞赛提示
> - 数组大小比题目最大值多开 5～10 个，给自己留余量。
> - 循环条件写清楚：遍历 `n` 个元素用 `i < n`，不是 `i <= n`。
> - 用 1-based 时，数组要开 `n + 1` 或更大。
