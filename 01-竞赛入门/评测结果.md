# 评测结果

> [!info] 一句话
> 评测状态告诉你程序“错在哪一类”，先看状态，再按方向排查，比盲目改代码快得多。

## 常见状态

| 状态 | 全称 | 意思 | 优先检查 |
| --- | --- | --- | --- |
| **AC** | Accepted | 全部测试点通过 | 做得好，可以复盘思路 |
| **WA** | Wrong Answer | 答案错误 | 逻辑、边界、输出格式、整数溢出 |
| **CE** | Compile Error | 编译失败 | 看第一条报错，改语法/头文件 |
| **TLE** | Time Limit Exceeded | 超时 | 算法复杂度，而不是先抠常数 |
| **MLE** | Memory Limit Exceeded | 内存超限 | 数组太大、递归太深 |
| **RE** | Runtime Error | 运行崩溃 | 数组越界、除零、空容器访问、爆栈 |
| **OLE** | Output Limit Exceeded | 输出过多 | 死循环里的 `printf` |
| **UKE** | Unknown Error | 评测机异常 | 重交一遍 |

## 每种状态怎么排查

### WA：答案错误

- 先测题目样例，再自己造边界数据（最小值、最大值、0、负数、重复元素）。
- 检查输出格式：空格、换行、小数位数、大小写。
- 检查整数溢出：`int` 相乘可能超过 $2.1 \times 10^9$，改用 `long long`。
- 检查循环边界：`< n` 还是 `<= n`，下标从 0 还是 1 开始。

### CE：编译错误

读**第一条**错误，定位行号。常见原因是少分号、括号不配对、全角标点、变量名拼错、头文件缺失。详细排查见 [[编译错误排查]]。

### TLE：超时

先估算复杂度：如果 $n = 10^5$，$O(n^2)$ 通常就会超时。换算法优先，不要先研究 `scanf` 快还是 `cin` 快。

### MLE：内存超限

数组元素个数 × 每个元素的字节数。例如 `int a[100000000]` 大约占 400MB，很容易超限。递归层数太深也会占用大量栈空间。

### RE：运行错误

常见原因：数组越界、除以 0、访问空 `vector`、递归爆栈、`scanf` 漏写 `&`。可以用小数据逐步缩小范围。

### OLE：输出超限

通常是循环没有终止条件，或者循环里不断输出。先检查 `while`/`for` 的退出条件。

> 很多比赛采用**子任务/测试点**计分：即使不会正解，写出暴力算法也可能拿到部分分。比赛时先保证能拿的分拿到，再想优化。理解复杂度有助于判断暴力能拿多少分，见 [[时间复杂度入门]]。
