# 学习资源与 IDE

> [!info] 一句话
> 工具不是重点，能写、能调试、能提交才重要。零基础阶段优先选择“少配置、能马上写题”的方案。

## 推荐资源

| 资源 | 用途 | 链接 |
| --- | --- | --- |
| 洛谷 | 主刷题平台、题单、比赛 | <https://www.luogu.com.cn/> |
| OI Wiki | 查知识点、看算法讲解 | <https://oi-wiki.org/> |
| cppreference | 查 C++ 语法和标准库细节 | <https://zh.cppreference.com/> |
| Codeforces | 进阶比赛、rating | <https://codeforces.com/> |
| AtCoder | 进阶比赛、题目质量高 | <https://atcoder.jp/> |

初学阶段不需要到处收藏资源，**洛谷题单 + OI Wiki** 已经够用。

## 用什么写代码

### 方案 A：洛谷在线 IDE（零基础推荐）

- 优点：免安装、打开网页就能写，提交方便。
- 缺点：调试功能有限，代码存在云端。
- 适合：刚开始学语法、做简单题。

### 方案 B：Dev-C++

- 优点：安装简单，适合新手，很多学校机房都有。
- 缺点：界面老，调试体验一般，默认标准可能偏旧。
- 建议：可以用，但不要把 Dev-C++ 的特殊行为当成 C++ 标准；逐步过渡到现代工具。

### 方案 C：VS Code + g++（长期推荐）

- 优点：代码补全、调试、插件生态好，适合长期使用。
- 缺点：需要自己配置编译器和调试环境。
- 适合：已经能独立写题、准备长期训练的同学。

> [!tip] 统一环境
> 本课程以 **C++14、GCC** 为准。在线提交时选择 C++14 (GCC 9) 或 C++17；本地写代码时尽量打开 `-std=c++14 -O2`，减少“本地能过、OJ 不过”的情况。

## 怎么用 AI 辅助

**可以这样用：**

- 把报错信息、相关代码一起贴给 AI，让它解释错误原因；
- 让 AI 帮你造几组边界测试数据；
- 让 AI 检查你的思路是否漏了情况，但自己判断对错；
- 让 AI 把一段代码改得更易读。

**不要这样用：**

- 直接复制 AI 生成的整题答案，不看不验证；
- 题目不会就先问 AI，跳过自己思考的环节；
- 把 AI 的输出当成正确答案——最终以 OJ 评测为准。

> [!warning] 学习原则
> AI 是助教，不是代打。能自己讲清楚为什么，才算真的会。

## 自学循环

```text
看题 → 独立思考 20～30 分钟 → 写代码 → 自测 → 提交
     → 看题解/问人 → 合上题解重写 → 总结错因
```
