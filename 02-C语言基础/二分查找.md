# 二分查找

> [!info] 一句话
> 二分查找在有序数组里每次丢掉一半——$O(\log n)$，十亿个数也只要约 30 次比较。

## 前提与直觉

二分之前，数组必须**有序**（或具有单调性）。每次拿中间的元素比较一次，就能确定"答案在左半边还是右半边"，丢掉另一半——所以 $n$ 每翻一倍，比较次数只多 1。

## 手写模板（左闭右开）

```cpp
// 返回第一个 >= x 的位置（没有则返回 n）
int lower(int a[], int n, int x) {
    int l = 0, r = n;                // 区间 [l, r)
    while (l < r) {
        int mid = l + (r - l) / 2;   // 等价于 (l + r) / 2，写法更稳
        if (a[mid] >= x) r = mid;    // mid 可能是答案，保留
        else l = mid + 1;            // mid 不可能是答案，跳过
    }
    return l;                        // 循环结束时 l == r，就是答案位置
}
```

把三点想透，模板就不用背：

1. 区间是 `[l, r)`——**右端取不到**，所以初始 `r = n` 而不是 `n - 1`；
2. `a[mid] >= x` 时，`mid` 本身可能是答案（它可以是"第一个"），所以 `r = mid` **不能减 1**；
3. `a[mid] < x` 时，`mid` 肯定不是答案，`l = mid + 1` 放心跳过。

## STL 版

前面在 [[STL常用函数]] 见过，这里正式对号入座：

```cpp
int pos = lower_bound(a, a + n, x) - a;   // 第一个 >= x 的位置
int cnt = upper_bound(a, a + n, x) - lower_bound(a, a + n, x);   // x 出现次数
```

`lower` 模板手写版和 `lower_bound` 是同一件事——比赛里直接用它。

## 找最后一个 <= x（变体）

对称地改条件即可，或者更省事：`upper_bound(a, a + n, x) - a - 1`（第一个 > x 的位置再往前一格）。

> [!warning] 常见坑
> - 数组**没排序**就二分：结果错得离谱，还不报错；
> - `l = mid` 死循环：`mid` 永远不缩小范围——记住两条更新里必须有一条是 `mid ± 1`；
> - 区间端点漏算：比如 `r = n - 1` 配 `while (l < r)`，最后一个元素就永远查不到。

> [!note] 预告
> 把"求最大/最小"变成"判断可行"，就是**二分答案**——砍树、跳石头那类题的正解，见 [[二分答案]]。
