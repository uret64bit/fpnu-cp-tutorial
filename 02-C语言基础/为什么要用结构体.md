# 为什么要用结构体

> [!info] 一句话
> 一个人的名字和分数本该是一个整体；拆成两个数组存，一排序就"散架"。

## 平行数组的麻烦

先看一段"看起来能用"的写法——把名字和分数分别存在两个数组里：

```cpp
char name[3][20] = {"Tom", "Amy", "Bob"};
int  score[3]    = { 90,   95,   88 };
```

读数据时 `name[i]` 和 `score[i]` 确实一一对应。但题目说"按分数从高到低输出名字"，问题就来了：

- 交换 `score[i]` 和 `score[j]` 时，**必须记得同时交换 `name[i]` 和 `name[j]`**；
- 交换要用临时变量，两处一起动，还要在循环里写对——忘一次，名字和分数就对不上，输出全乱。

数据本身是绑在一起的，代码里却被拆成两半，这就是"平行数组"的根本毛病。

## 打包成一条记录

把"一个学生"打包成一个整体：

```cpp
struct Student { char name[20]; int score; };

Student a[3] = { {"Tom", 90}, {"Amy", 95}, {"Bob", 88} };
// 交换 a[i] 和 a[j]：名字和分数整体一起动，不会散
```

`a[i]` 就是一个完整的学生——名字和分数永远在一起，交换、排序、搬来搬去都是"整条"的事，不可能只动一半。

## 什么时候该用

多个字段**总是一起出现**、说的是"一条记录"的时候：

- 学生：姓名 + 分数；
- 商品：名称 + 价格 + 数量；
- 日期：年 + 月 + 日；
- 平面上的点：横坐标 + 纵坐标。

反过来说，如果题目里几个数组本来就没关系（`a[]` 和 `b[]` 各算各的），就不用硬凑。

## 这还只是开始

结构体的真正威力在排序：给 `cmp` 指定一个字段，就能让整个"学生数组"按分数排队，名字和分数整条跟着走：

```cpp
bool cmp(Student x, Student y) {
    return x.score > y.score;   // 分数高的排前面
}
sort(a, a + 3, cmp);
```

结构体 + 排序是"排行榜""成绩单"类题目的标准解法，正是 Day 4 作业要练的，具体写法见 [[排序]]。
