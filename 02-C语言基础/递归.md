# 递归

> [!info] 一句话
> 递归就是"函数自己调用自己"：把大问题缩小成一个同样的小问题，缩到最小（边界）就停下。

## 三要素

写递归前先想清三件事：

1. **边界条件**：最小的情况直接给出答案（不想这一步，函数会无限调用自己）；
2. **规模缩小**：每次调用必须离边界更近（`n` → `n - 1`）；
3. **调用自身**：用"缩小后问题的答案"拼出当前问题的答案。

## 例：阶乘

```cpp
int fact(int n) {
    if (n <= 1) return 1;       // ① 边界：0! = 1! = 1
    return n * fact(n - 1);     // ② 缩小 + ③ 调用自身
}
```

算 `fact(4)` 的过程：等 `fact(3)` → 等 `fact(2)` → 等 `fact(1)`，边界返回 1，再一路乘回来：`1 × 2 × 3 × 4 = 24`。

## 例：斐波那契

数列：1, 1, 2, 3, 5, 8, …（每一项是前两项之和）

```cpp
int f(int n) {
    if (n <= 2) return 1;
    return f(n - 1) + f(n - 2);
}
```

看起来优雅，但**朴素递归非常慢**：算 `f(40)` 会把同一个子问题重复算几百万次。解决办法是"算过一次就记下来"（记忆化），后面的搜索讲次会学。

## 递归与调用栈

每一次调用都会在内存里开一层"自己的工作台"：这一层的形参 `n` 和上一层的 `n` 各是各的。

- 层数太深（比如递归一万层）会**爆栈**，程序直接 RE——`main` 里开大数组爆栈是同一个道理（见 [[数组]] 的拓展段）；
- 所以递归深度心里要有数，别无限往下走。

## 递归还是循环？

- **能用循环就用循环**：快、不怕深、好调试；
- **递归适合**：问题天然能拆成"同样的小问题"——树的遍历、搜索、分治。搜索讲次会大量用到。

> [!tip] 竞赛提示
> 写递归的固定顺序：先写**边界**，再写缩小和调用。调不通时在函数第一行 `printf("n=%d\n", n);` 打印每一层的参数，看清是没到边界、还是规模没缩小。
