# 隐式转换

> [!info] 一句话
> 隐式转换是编译器**自动**完成的类型转换：小的类型向大的类型转是安全的（`char → int → long long → double`），大的向小的转可能丢数据。理解它，才能解释"为什么 `a / b` 得 0""为什么乘积悄悄变成负数"。

## 转换方向（从小到大）

```text
char / short → int → long long → double
```

表达式里出现不同类型时，编译器把"小"的转成"大"的再运算，结果是"大"的那个类型：

```cpp
int a = 5;
double x = 3.14;
double sum = a + x;   // a 先隐式转成 double(5.0)，再相加
```

## 赋值时的隐式转换

赋值语句里，右边的值会转成左边变量的类型：

```cpp
int n = 3.99;      // n = 3：小数部分被截断（不是四舍五入）
double d = 7;      // d = 7.0：小转大，安全
char c = 300;      // 300 超出 char 范围，结果不是 300
```

> [!warning] 大转小会丢数据
> `int → double` 安全；`double → int` 截断小数；`int → char`、`long long → int` 超出范围时结果不可预期（常见是"回绕"，见 [[整数在内存中的表示]]）。

## 运算中的隐式转换（高频考点）

### 字符参与运算会先变成 int

```cpp
printf("%d\n", 'A' + 1);   // 66：'A' 隐式转成 65
char c = '7';
int x = c - '0';           // 7：字符先转成 ASCII 码再相减
```

### 整数除法不会自动变成小数

```cpp
int a = 1, b = 2;
printf("%d\n", a / b);           // 0：两个 int 运算，结果仍是 int
printf("%.2f\n", (double)a / b); // 0.50：手动先转一个操作数
```

`a / b` 不会"提升"成除法小数——两个操作数同类型时根本不需要转换。**想要小数，至少让一个操作数是 `double`**。

### int 乘法不会"提到 long long"

```cpp
int a = 100000, b = 100000;
long long c = a * b;              // 错：先按 int 算，结果已经溢出
long long d = (long long)a * b;   // 对：先转再乘
```

左边是 `long long` 救不了右边——**转换发生在运算之后**，溢出在运算时就已经发生了。

## 易错点

- `double x = a / b;` 里虽然 `x` 是 `double`，但 `a / b` 已经按整数算完，再转也救不回来。
- `if (x)`、`while (n--)` 里，数值会隐式转成 `bool`：0 为假，非 0 为真。
- `printf` 的格式符**不会触发转换**：`%d` 配 `long long` 变量是未定义行为，必须写 `%lld`。

> [!abstract] 拓展 · 选读
> 有符号数与无符号数混用会触发另一套转换规则，结果反直觉：
> ```cpp
> printf("%d\n", -14 % 7u);   // 常见输出 4，而不是 0
> ```
> 运算时 `-14` 被转成无符号数（$2^{32}-14$）再取余。竞赛里统一用 `int` / `long long`，不混 `unsigned`。

## 竞赛提示

- 除法/分数题先想清楚"要整数还是小数"；要小数就写 `(double)a / b`。
- 大数乘法先转再乘：`(long long)a * b` 或 `1LL * a * b`。
- 输出 `long long` 用 `%lld`——格式符不会帮你自动转换。
