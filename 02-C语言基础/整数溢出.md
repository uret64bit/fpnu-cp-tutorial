# 整数溢出

> [!info] 一句话
> 运算的**中间结果**超过类型的表示范围就会溢出，结果不可预期（常见的是按补码"回绕"成负数或怪值）。乘法、累加是高发区——先估算最大值，再挑类型。

## 什么时候会溢出

`int` 上限约 $2.1 \times 10^9$（见 [[基本数据类型]]）。只要**运算过程中任何一步**超过它，即使最终答案没那么大，也会溢出：

```cpp
int a = 100000;
printf("%d\n", a * a);   // 10^10 超出 int，结果不可靠

int n = 100000, sum = 0;
// n 个 10^9 累加是 10^14，sum 用 int 必然溢出
```

读题拿到数据范围后，把**过程中最大的中间值**估算一遍，和类型上限对照。

## 怎么防

### 乘法：转换必须在乘法之前

```cpp
int a = 100000;
long long c = a * a;             // 错：先按 int 算，溢出已经发生
long long d = 1LL * a * a;       // 对：1LL 把运算"抬高"到 long long
long long e = (long long)a * a;  // 对：等价写法
```

左边变量是 `long long` 救不了右边——转换发生在运算之后，原理见 [[隐式转换]]。

### 累加：sum 直接开 long long

```cpp
long long sum = 0;   // 每个数都在 int 范围，总和不一定
```

### 取模题：中间乘法也要 long long

题目要求"答案对 $10^9+7$ 取模"时，`(a * b) % MOD` 里的 `a * b` 可能到 $10^{18}$——先转 `long long` 再乘，取模救不了已经溢出的乘法。

## 溢出之后会发生什么

不报错。结果按补码回绕成负数或不相干的数，程序带着错误结果继续跑，最后 WA 得莫名其妙。原理见拓展 [[整数在内存中的表示]]。

## 易错点

- 输出 `long long` 必须用 `%lld`：用 `%d` 会把 8 字节按 4 字节解释，打印怪值。
- `-2147483648`（`INT_MIN`）取相反数会溢出——2147483648 超出 int 范围，结果仍是负数。
- **看答案的规模，不只看输入**：输入在 int 范围，不代表答案也在。

## 竞赛提示

- 看到"$a \times b$，$a, b \le 10^9$"或"对 $10^9+7$ 取模"，先想 `long long`。
- 估算不清中间值时，**宁可全开 long long**，性能损失可以忽略。
