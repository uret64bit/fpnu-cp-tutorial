# 竞赛代码模板

> [!info] 一句话
> 比赛时从一个固定模板开始，能少写重复代码，减少“忘写分号、忘加头文件”这类低级错误。

## 推荐模板

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 你的代码写在这里

    return 0;
}
```

## 模板解释

- **`#include <bits/stdc++.h>`**：GCC 编译器提供的“万能头文件”，一次包含大多数标准库。
  - 优点：不用每次记 `<cstdio>`、`<algorithm>`、`<vector>` 等头文件。
  - 注意：它不是 C++ 标准，其他编译器可能不支持；洛谷使用的 GCC 支持它。
- **`using namespace std;`**：让 `sort`、`vector` 等标准库名字可以直接写，不用加 `std::`。
- **`int main()`**：程序入口。C++ 标准要求 `main` 返回 `int`。
- **`return 0;`**：表示程序正常结束。

## 输入输出怎么写

初学阶段统一使用 `scanf` / `printf`：

```cpp
int a, b;
scanf("%d%d", &a, &b);
printf("%d\n", a + b);
```

原因：

- 格式符和题目要求一一对应，便于检查；
- 读入大量数据时通常比默认的 `cin/cout` 快；
- 后续算法题中不容易因为输入输出被卡。

> [!tip] 关于 `cin/cout`
> 可以用，但有大数据量时要加：
> ```cpp
> ios::sync_with_stdio(false);
> cin.tie(nullptr);
> ```
> 初学阶段不要混用 `cin/cout` 和 `scanf/printf`，避免输入顺序错乱。

> [!note] 预告 · 第 6 讲
> 模板里的 `main` 本身就是一个函数。第 6 讲会学**自己定义函数**：参数、返回值、作用域与递归，把重复代码抽出来复用。到时候你的模板会多出几个自己的小工具函数。

## 提交前检查

- [ ] 选择 C++14 或 C++17（洛谷选 `C++14 (GCC 9)`）。
- [ ] 没有写 `freopen`，除非题目明确要求文件输入输出。
- [ ] 没有把调试输出留在代码里。
- [ ] `long long` 的结果用 `%lld` 输出。
- [ ] 模板里的注释可以删掉，不影响运行。

> [!warning] `bits/stdc++.h` 不是“万能正确”
> 它只是方便，不会让错误代码变正确。算法错误、数组越界、整数溢出，它都救不了。
