# 链表

> [!info] 一句话
> 链表用“结点 + 指针”把数据串起来，插入删除不用整体搬移，代价是不能按下标直接访问。

## 为什么需要链表

数组在中间插入或删除一个元素时，后面的元素都要往后挪或往前挪，单次操作 $O(n)$：

```cpp
// 在下标 k 处插入 x：k 后面的元素全部后移
for (int i = n; i > k; i--) a[i] = a[i - 1];
a[k] = x;
```

如果题目频繁在某个位置插入/删除，数组就很吃亏。链表把“相邻关系”从**连续内存**改成**指针记录**，插入删除只需要改几条指针。

## 结点与链

链表的每个元素叫**结点**，至少存两样东西：值，以及下一个结点的地址。

```cpp
struct Node {
    int val;
    Node *next;
};
```

多个结点通过 `next` 一个指一个，最后一个结点的 `next` 是 `nullptr`（空指针），表示链结束。第一个结点叫**头结点**，用 `head` 指针记录：

```text
head → [1] → [2] → [3] → nullptr
```

## 插入与删除

在结点 `p` 后面插入一个新结点：

```cpp
Node *q = new Node{v, p->next};   // 新结点先接上 p 原来的后继
p->next = q;                      // 再让 p 指向新结点
```

删除 `p` 后面的结点：

```cpp
Node *t = p->next;       // 记住要删的结点
p->next = t->next;       // 跨过它
delete t;                // 竞赛里漏写一般也能过，但好习惯是释放
```

顺序不能反：如果先写 `p->next = q`，就找不到原来的后继了。

### 头插与哨兵

在链表头部插入，需要更新 `head`：

```cpp
Node *p = new Node{v, head};
head = p;
```

每次特判“空链表/操作头结点”很烦，常用一个不存数据的**哨兵结点**（dummy head）：

```cpp
Node *dummy = new Node{0, nullptr};   // dummy->next 才是真正的第一个元素
// 之后所有插入删除都变成“在某个结点后面操作”，不用改 head
```

## 遍历

```cpp
for (Node *p = head; p != nullptr; p = p->next) {
    printf("%d ", p->val);
}
```

链表**不能**写 `head[i]`，也不能用 `p + 1` 跳到下一个——只能顺着 `next` 一个一个走，所以按位置访问是 $O(n)$。

> [!abstract] 拓展 · 选读
> **数组模拟链表（静态链表）**：竞赛里更常见，用下标代替指针，避免 `new/delete`，也方便调试。
>
> ```cpp
> int val[N], nxt[N], pre[N];
> // 用 0 号结点当哨兵：nxt[0] 指向第一个元素，pre[0] 指向最后一个元素
> ```
>
> 在 `x` 右边插入 `y`：
>
> ```cpp
> nxt[y] = nxt[x];
> pre[y] = x;
> pre[nxt[x]] = y;
> nxt[x] = y;
> ```
>
> 删除 `x`：
>
> ```cpp
> pre[nxt[x]] = pre[x];
> nxt[pre[x]] = nxt[x];
> ```
>
> 双向链表多存一个 `pre`，就能 $O(1)$ 找到前驱；P1160 队列安排就是双向链表的模板题。

> [!warning] 易错点
> - **空指针**：访问 `p->next` 前先确认 `p != nullptr`，尤其是 `p->next->next` 这种连跳。
> - **删除后断链**：先把前后接好，再释放结点；删除后不要再访问已释放的内存。
> - **头结点特判**：不用哨兵时，在头部插入/删除要单独改 `head`。
> - **数组模拟**：初始化 `nxt[0] = 0; pre[0] = 0;`，插入删除时别忘了维护哨兵两端的指针。

> [!tip] 竞赛提示
> 能用 [[vector]] 解决就少手写指针链表：`vector` 的尾部插入删除是 $O(1)$，随机访问也方便。只有题目明确要求“在任意位置 $O(1)$ 插入删除”时才考虑链表；链表题又常考**数组模拟**，因为不用处理指针和内存。
